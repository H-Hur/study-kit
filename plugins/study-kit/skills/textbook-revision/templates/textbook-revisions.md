# Textbook revisions pending

The file that accumulates what is to be folded into the next revision of
the recorded authoritative source (by default `docs/textbook.html`).

**Operating rules**

- Routes that fill it: ① the learner's questions (session conversation, recovered from the
  secondary track) ② items in a comprehension audit report worth reflecting in the textbook
  ③ errors or unclear passages exposed during practice ④ improvements the author promised
  ⑤ direct edits, comments, or tracked changes in delivered files. For direct edits,
  record whole-content differences, before/after wording or structural changes, and
  their disposition; preserve user deletions and resolve source conflicts.
- Write each item out **as far as the revised wording (the sentence that will actually go
  in)** — so that nothing has to be reconstructed at revision time.
- Queue corrections before changing the master, unless the user explicitly requests
  an earlier master edit. Apply them at the project's recorded publication trigger.
- When that trigger is met, open this file first and apply the authorized waiting
  items. Track applied-but-unpublished items so retries do not apply them twice.
  Move an item to the reflection history as `reflected (edition N)` only after
  the requested publication artifacts pass verification.
- All wording keeps the dual-audience convention (self-standing prose; fundamentals go in
  groundwork boxes).
